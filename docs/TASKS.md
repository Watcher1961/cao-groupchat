### 第 3 项：启动投递与无进展恢复（已结案）

第 3 项历史实施范围为本项和群主明确附带的两项小事，彼时未实现第 4 项群启动竞态或第 5 项抽屉布局。每个提交仍交 Claude 审查；调度只快速核对，不自审；额度耗尽时本地标待审，不进入依赖项。

就绪设计依据：本机 CAO `providers/codex.py` 的 `TUI_FOOTER_PATTERN` 注明 raw FIFO 不一定有可见提示箭头，使用 shortcuts/context/path 页脚辅助识别；Codex initialize 等待 CLI 状态并排除启动对话框。`providers/claude_code.py:1045` 的 `wait_until_input_ready` 在渲染屏幕上检查输入框及两次约 0.5 秒稳定捕获，且 initialize 在 gate 超时后仍可能继续。公开 terminal 模型没有统一 input-ready 字段。因此 GUI 使用 raw full 尾部的正向提示特征、idle/completed 状态、至少两次且间隔达标的稳定观察；不是固定 sleep 到点就发。

Codex 特征为 shortcuts/context/path 页脚且不是 working；Claude 为新 TUI 横线输入框（空或带 Try 占位提示）或旧版行尾空提示符。raw 稳定不等价于渲染屏幕稳定，版本/主题/启动权限菜单仍待真实联调；群主在 aad5a16 的 Claude 冷启动已通过，Codex 消息虽送达但 GUI 漏收，重开记录见下文。其他 provider 仅有非空输出加稳定 ready 状态的兼容路径，不新增真实兼容承诺。

消息设计：未取得 terminal 或未证明就绪时保存成员待投递队列；就绪后按顺序投递。投递后以本轮工作证据确认启动（Codex working；Claude fresh busy/等待确认），再由新输出刷新无进展时钟；不以重复 idle/busy 或无启动证据的重绘无限续期。超时提示“可能未送达”，UI 显示可重发状态；不自动重发，保留原消息及跳数，并用投递 ID/次数防止重复点击。

默认时限为就绪稳定 0.75 秒、启动等待 180 秒、投递无进展 120 秒，轮询 2 秒；配置分别为 GROUPCHAT_READY_SECONDS / GROUPCHAT_STARTUP_TIMEOUT / GROUPCHAT_DELIVERY_TIMEOUT / GROUPCHAT_POLL_SECONDS（有限正数秒）。隔离集成配置为 0.06 / 2 / 0.6 / 0.03 秒，靠阶段 gate 和带截止时间轮询控制，不用固定 sleep 猜就绪。

### 第 4 项：并发重启竞态（已结案）

群主授权范围：同群所有成员离线时多个启动同时进入，不能各自 POST /sessions；同群只建一次，其余加入，不同群互不阻塞；一个成员启动失败不能卡住其他成员。不实现第 5 项窄窗口抽屉。

依据：本机 CAO `api/main.py:4015` 提供 GET /sessions/{session_name}，不存在为 404；群主确认重复 POST /sessions 为 400、正文含 `Session '…' already exists`。原代码把“没有在线成员”当成会话不存在，故即使没有并发，只剩空会话时也会重复创建。

实现：每群独立的进程内 RLock，覆盖会话探测、创建/加入及终端标识发布；安装 profile 在锁外，网络操作不持全局状态锁。先查询已记录 session_name（或 session_slug）；存活时走 :operator 加入，即使在线成员为零；404 或 session.status=terminated 才创建（terminated 修复见下文）。查询与创建间外部进程抢先建成时，仅精确重复会话的 400 转加入，不吞其他错误。加入 404 时最多直接尝试创建一次，不再重复查询可能残留的失败记录；保留旧版 :operator 404/405 且有 live caller 时的兼容路径。异常由 with 释放群锁，未用会导致永久等待的创建中标志。

fake 对 session 单独建模：删完终端保留空会话，显式删会话才移除；提供查询、创建/加入调用记录；同名重复创建严格返回 400 和真实错误正文；缺失会话加入返回 404。按会话 Event 阻塞、按 profile 注入失败均只用于测试，阻塞时不持 fake 全局锁，防止测试替身错误串行化所有群。
